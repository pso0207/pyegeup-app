# 디자인 규약

**토큰 원본은 [`../DESIGN.md`](../DESIGN.md)** (에이전트가 읽는 규격 파일)이고,
값의 출처는 `constants/theme.js`입니다. 둘의 동기화는 `node scripts/check-design.mjs`가 검사합니다.

이 문서는 그 위에 **"왜 이 숫자인가"** 를 적습니다. UI를 고치기 전에 읽으세요.

## 톤

**종이 + 잉크 + 의미색.** 미색 종이(`#F4F2EC`) 위에 흰 서류(`#FFFFFF`)를 얹고
따뜻한 잉크(`#17160F`)로 씁니다. **색이 붙은 것은 뜻이 있는 것뿐**입니다.

```
bg          #F4F2EC   미색 종이 (바닥)
bgElevated  #FFFFFF   탭바 · 시트 · 세그먼트 트랙
surface     #FFFFFF   흰 서류 (카드 · 목록판)
surfaceAlt  #EBE8E0   서류 위 한 겹 — 라이트에서 대비가 가장 까다로운 배경
border      #CFC9BA / borderSoft #E1DCD1

text        #17160F / textMuted #56524A / textFaint #6B665B

accent      #17160F   강조 = 잉크 (잉크 버튼 + 미색 글자)
onAccent    #FAF9F5   잉크 버튼 위 글자
brand       #B3271B   인주(印朱) — 도장 · 안 읽은 배지

guilty      #B3271B   무죄 innocent #1D6B44
close       #8F5408   초박빙
ticket      #8A6114   티켓(재화)
gold/silver/bronze     1·2·3위 메달
```

### 왜 다크를 버렸나

팔레트를 세 번 갈았습니다: 딥네이비+황동 → 무채색 다크 → **종이 라이트**.
앞의 둘 다 "AI가 만든 티가 난다"는 지적을 받았고, 두 번째 지적에서
**문제가 색이 아니라 매체**라는 게 드러났습니다.

| 근거 | 내용 |
|---|---|
| 읽기 | 이 앱에서 제일 오래 하는 일은 4칸 사연을 읽는 것입니다. 획이 많은 한글은 어두운 배경에서 halation(흰 글자 번짐)이 라틴보다 심합니다 |
| 은유 | "재판"은 문서의 세계입니다 — 판결문·서류·도장·판례집 |
| 관습 | 한국 커뮤니티는 전부 라이트 기본입니다 — 디시·에타·네이트판·더쿠·클리앙 |
| 차별화 | 검정 배경 + 흰 강조 버튼 + 채도 높은 의미색은 **현재 AI 생성 UI의 최빈값**입니다 |

**강조에 채도색을 쓰지 않는 이유**는 그대로입니다. 강조가 파랑이나 금색이면 유죄 적색과
신호가 겹쳐 둘 다 약해집니다. 강조를 잉크로 두면 적/녹만 뜻을 갖습니다.

### 다크는 개표 3초에만 남았다

`constants/theme.js`의 `dark` 팔레트로 살아 있고 `app/case/result.js`에서만 씁니다.
화면 전체가 처음부터 어두우면 개표의 게이지 역전 연출이 배경에 묻힙니다.
밝게 읽다가 불이 꺼지고, 확정되는 순간 조명이 다시 올라와야 그게 **선고**로 읽힙니다.

`dark` 팔레트도 `scripts/check-design.mjs`가 대비를 검사합니다 —
문서에는 안 적지만 실제로 화면에 나가는 색입니다.

### 함께 걷어낸 것

| 걷어낸 것 | 왜 |
|---|---|
| **사건 카드 → 목록 행** | 박스에 담으면 390px에 사건이 2.5개 들어갑니다. 게시판은 12~15줄이 떠야 훑힙니다 |
| **Tailwind 400번대 법원 6색** | `#F472B6 #A78BFA #2DD4BF` — 어느 앱에서나 본 색. 가장 큰 AI 지문이었습니다 |
| **메타 아이콘(사람·문서·자물쇠)** | `1,240표 [96]` 텍스트가 짧고 빠릅니다. 대괄호 댓글수는 한국 게시판의 관습 |
| **판례집 코너 2열 카드 격자** | 격자는 대시보드의 문법입니다. 상단 말머리 탭 한 줄로 접었습니다 |
| **탭·섹션 제목 아이콘** | 한국어 라벨은 두세 글자라 아이콘이 뜻을 더하지 않습니다 |
| **eyebrow(제목 위 작은 라벨)** | SaaS 랜딩의 문법이고 읽는 순서를 뒤집습니다. 제목 아래로 내렸습니다 |
| **`DAILY 5` `LIVE` 영문 라벨** | 한국 커뮤니티에 영문 대문자 라벨은 없습니다 |
| **`radius.xl` 14 → 10** | 서류는 각집니다. 둥글수록 위젯, 각질수록 문서 |
| **3열 대형 숫자 스탯** | `판사 지수 3,310 / 적중률 73% / 판결 수 402` — 대시보드의 대표 부품. 표 세 줄로 접었습니다 |
| **게이미피케이션 게이지 7곳** | `부장판사까지 2,190점`이 진행바보다 정확하고 짧습니다. `IndexDial` 컴포넌트는 삭제. **뜻이 있는 게이지(`VerdictBar` · 개표 · 폼 진행률)는 남깁니다** |
| **흰 둥근 카드 쌓기** | 상자를 세로로 쌓으면 화면이 정보가 아니라 위젯 묶음으로 읽힙니다 → `Section` + 괘선 |
| **세그먼트 컨트롤** | 둥근 트랙 + 미끄러지는 알약. 잘 만든 부품이라서 문제였습니다 → 밑줄 탭 |
| **랭킹 시상대** | 단상 + 메달 아이콘은 게임의 문법. 1~3위도 같은 목록에 넣고 순위 숫자만 메달색 |
| **정사각 아이콘 타일** | 티켓 획득 6줄이 각각 카드 + 아이콘 타일이었습니다 → 요금표 한 장 |
| **그라디언트 · 그림자** | 목록에 그림자를 깔면 정보가 아니라 위젯으로 읽힙니다 |

`shadow` 토큰은 호출부 호환을 위해 남겨두고 값만 비웠습니다. 새 코드에서는 쓰지 마세요.

## 접근성 수치 (근거 있는 값)

바꾸기 전에 왜 이 숫자인지 확인하세요. 감이 아니라 표준에서 온 값입니다.

### 대비 — WCAG AA 4.5:1

라이트에서 **가장 까다로운 배경은 `bg`가 아니라 `surfaceAlt`(`#EBE8E0`)** 입니다.
칩 · 빈 상태 아이콘 · 입력 배경이 이 색이라, 여기서 통과하지 않으면 실사용에서 깨집니다.
다크 시절에는 두 배경만 봤지만 지금은 **세 배경 전부** 확인합니다.

| 색 | on bg | on surface | on surfaceAlt |
|---|---|---|---|
| text #17160F | 16.20 | 18.13 | 14.81 |
| textMuted #56524A | 6.94 | 7.77 | 6.35 |
| **textFaint #6B665B** | 5.10 | 5.71 | **4.66** |
| guilty #B3271B | 5.82 | 6.52 | 5.32 |
| innocent #1D6B44 | 5.79 | 6.48 | 5.30 |
| close #8F5408 | 5.45 | 6.11 | 4.99 |
| ticket #8A6114 | 4.94 | 5.53 | **4.51** |

`textFaint`와 `ticket`이 `surfaceAlt` 위에서 간당간당합니다. 이 두 색을 조금이라도
밝히면 바로 미달이 되니 건드리지 마세요.

`scripts/check-design.mjs`가 이 검사를 자동으로 돌립니다 —
법원 6색과 메달 3색, 다크 팔레트까지 전부 포함합니다.

### 빨강이 하나로 줄었다

다크 시절 `brand`와 `brandFill`은 값이 달라야 했습니다. **대비 요구가 정반대**였기 때문입니다:
어두운 배경 위 **글자**는 밝아야 하고(`#FF4D57`), 흰 글자를 얹는 **채움**은
어두워야 했습니다(`#DC2029`). 하나로 합치면 반드시 한쪽이 깨졌습니다.

**종이 위에서는 이 충돌이 사라집니다.** 어두운 인주 빨강 `#B3271B` 하나가 양쪽 다 통과합니다:

| 용도 | 대비 |
|---|---|
| 종이 배경 위 글자 | 5.82:1 |
| 흰 서류 위 글자 | 6.52:1 |
| 흰 글자를 얹는 채움 | 6.52:1 |

두 토큰은 호출부 호환을 위해 남아 있고 값이 같습니다.
**`dark` 팔레트에서는 여전히 둘로 갈라야 합니다** — 그쪽은 어두운 배경이니까요.

그래도 원칙은 그대로입니다. 배지·칩처럼 색을 채우는 요소를 만들 때는
**글자색이 아니라 채움색 기준으로** 계산하세요. 이걸 놓쳐서 다크 시절
**안 읽은 알림 배지가 흰 배경에 흰 글자**로 나간 적이 있습니다.

**채움색을 쓰는 곳 전수 검증**

| 요소 | 채움 | 글자 | 대비 |
|---|---|---|---|
| 기본 버튼 · 할 일 배지 · 토스트 | `accent` | `onAccent` | 17.21 |
| 무죄 버튼 | `innocent` | `onAccent` | 6.23 |
| 유죄 버튼 · 형량 활성 · 알림 배지 · 위험 확인 | `brandFill` | `#FFF` | 6.52 |

### 글자 크기 배율 — 크롬만 상한

본문은 시스템 글자 크기를 따라야 하지만, **고정 높이 안에 들어가야 하는 크롬**
(탭바 라벨, 배지, 칩)은 배율 상한을 겁니다.

```jsx
<Text maxFontSizeMultiplier={1.2}>  // 탭 라벨 · 배지
<Text maxFontSizeMultiplier={1.3}>  // 칩
```

Android 글자 크기를 1.6배로 올리면 탭바 라벨이 잘렸습니다.
본문에는 상한을 걸지 마세요 — 잘 늘어나는 것을 확인했습니다.

**테스트:**
```bash
adb shell settings put system font_scale 1.60   # 최대치
adb shell am force-stop host.exp.exponent       # 재시작해야 반영됨
# ... 확인 후
adb shell settings put system font_scale 1.00
```

### 터치 표적 — 최소 44dp

Material 48dp · Apple 44pt · WCAG 2.5.5 44px. `constants/theme.js`의 `hit` 토큰:

```js
export const hit = { min: 44, box: 40, slop: 12 };
```

**아이콘만 있는 버튼은 `components/IconButton.js`를 쓰세요.** 40×40 실제 박스를 잡습니다.

`hitSlop`으로 때우면 두 가지가 잘못됩니다:
1. RN Web에서는 `hitSlop`이 적용되지 않아 웹에서는 아이콘 크기 그대로입니다.
2. **아이콘을 나란히 두면 hitSlop이 서로 겹칩니다.** 실제로 사건 상세 헤더에서
   북마크(17px)와 메뉴(19px)가 gap 10 · hitSlop 10이라 **10px 구간이 겹쳐,
   북마크 오른쪽을 누르면 메뉴가 열리고 있었습니다.**

줄에 아이콘을 나란히 둘 땐 `gap`을 0~4로 좁히고 각각 40×40 박스를 잡으세요.
박스는 겹치지 않으므로 어느 지점을 눌러도 의도한 버튼이 눌립니다.

**글자만 있는 링크도 표적입니다.** `SectionTitle`의 "판례집 ›" 같은 것은
글자 높이가 20dp뿐이라, `paddingVertical: 12` + 같은 크기의 음수 마진으로
레이아웃을 안 밀면서 표적만 키웁니다.

### 검증 방법

렌더된 DOM에서 실제로 재세요. 눈으로는 못 잡습니다.

```js
// 40dp 미만 표적 찾기 — docs/TESTING.md의 tap.mjs
[...document.querySelectorAll('[role="button"],[role="tab"],[role="link"]')]
  .map(e => e.getBoundingClientRect())
  .filter(r => r.height < 40 || r.width < 40)
```

이 검사로 **22곳을 찾아 0곳으로 만들었습니다.** 최악은 사건 카드의
스크랩 버튼 **14×15px**(홈 피드에 5개)이었습니다.

## 한글 타이포

한글 UI 권장값(iOS 본문 17pt · Android 최소 16sp 기준을 한글에 맞춰 조정):

| 항목 | 값 | 왜 |
|---|---|---|
| 본문 크기 | **15.5~16px** | 15px 미만은 한글에서 작습니다 |
| 행간 | **155~175%** | `body` 26/15.5 = 1.68, `read` 28/16 = 1.75 |
| 자간 | **-0.3** | 한글은 라틴보다 좁혀야 덩어리로 읽힙니다 |

라틴 기준 행간(1.4~1.5)을 그대로 쓰면 긴 사연이 읽히지 않고,
자간 0을 쓰면 한글이 헐거워 보입니다. 제목은 커질수록 자간을 더 좁힙니다
(`h1` -0.7, `display` -0.9).

`type` 스케일: `display · h1 · h2 · h3 · body · read · bodyStrong · small · tiny · mono · label`

숫자가 세로로 정렬되는 곳(점수 · 표수 · 순위)에는 `type.mono`를 쓰세요 — `tabular-nums`가 들어 있습니다.

## 레이아웃

**모든 화면은 `layout.content`(최대 560px)로 가운데 정렬**합니다.
태블릿과 웹에서 글줄이 가로로 늘어지지 않게 하는 장치입니다. 새 화면도 반드시 적용하세요.

```js
contentContainerStyle={[{ padding: 16, gap: 16 }, layout.content]}
```

## 목록은 카드가 아니라 행이다

이 앱에서 가장 큰 레이아웃 결정입니다.

이전에는 사건 하나가 `rounded 12 / border 1 / padding 15` 박스였고, 제목 + 쟁점 2줄 +
아이콘 메타를 담았습니다. **390px 화면에 사건이 2.5개** 들어갔습니다.
디시 · 클리앙 · 에브리타임은 한 화면에 12~15줄이 뜨고,
**그 밀도가 훑어보는 재미의 전부**입니다.

지금은 `CaseList`(흰 서류판)에 `CaseCard`(행)를 쌓습니다:

```
 1 │ [직장] 팀 회식 중간에 말없이 집에 갔습니다              🔖
   │ 2026고합1174 · 1,240표 [96]            3시간 3분
```

지켜야 할 것 세 가지:

1. **제목 1줄 고정.** 행 높이가 전부 같아야 눈이 리듬을 탑니다.
2. **메타 1줄 고정.** 줄바꿈되는 순간 행 높이가 두 배가 되고 밀도가 통째로 무너집니다.
   각 조각에 `numberOfLines={1}`과 `flexShrink: 0`을 **함께** 걸어야 합니다
   (하나만으로는 RN이 접습니다).
3. **좌측 열은 "이 행의 신분".** 데일리 목록은 순번(디시의 글번호 열), 판례집은 확정 도장.

### 표와 괘선 — 이 앱의 기본 부품

목록을 행으로 바꾼 뒤에도 나머지 화면은 여전히 **카드 · 큰 숫자 · 진행바 · 알약** 네 부품으로
만들어져 있었고, 그게 두 번째 "AI 느낌"의 원인이었습니다.

| 대신 쓸 것 | 무엇 |
|---|---|
| `Facts` | 표. 라벨 왼쪽 · 값 오른쪽(`tabular-nums`) · 사이에 괘선 |
| `Section` | 제목 + 괘선 + 내용을 **종이 위에 그대로**. 상자로 감싸지 않는다 |
| `Rule` | 괘선 한 줄 |
| `Segmented` | 밑줄 탭 |

`Card`는 진짜로 "떠 있어야" 하는 것에만 남깁니다 — 데일리 공고, 내 사건 알림 배너.

예: 배심원 프로필의 `판사 지수 / 적중률 / 판결 수` 3열 대형 숫자 + 승급 진행바 +
자물쇠 안내 상자가 **표 여섯 줄**이 되면서 화면 하나에 다 들어왔습니다.

### 말머리 · 사건번호 · 도장

세 가지가 이 앱을 "게시판이자 법원"으로 만듭니다.

| 장치 | 형태 | 어디 |
|---|---|---|
| 말머리 | `[직장]` `[초박빙]` | `COURTS[].short`. 색 알약을 대체합니다 |
| 사건번호 | `2026고합1174` | `caseNoOf()`. 법원 사건번호이자 게시판 글번호 |
| 도장 | `Stamp` / `StampChip` | 확정 사건·판결. **-11도 기울여 찍습니다** |

도장이 수평이면 UI 배지로 읽히고, 기울면 "찍힌 것"으로 읽힙니다 —
이 앱에서 그 차이가 정체성입니다.

사건번호에는 `type.docNo`를 쓰세요. **본문과 반대로 자간을 벌리고**(`+0.3`)
숫자폭을 고정해서(`tabular-nums`) 목록에서 세로로 정렬됩니다.

## 읽기와 쓰기를 분리

- **읽기**(사건 상세) — 네 칸을 카드 안에 흐르게 두고, 쟁점만 왼쪽 굵은 선으로 따로 세웁니다.
- **쓰기**(투고 · 판결문 · 반박) — 미색 종이 위에 흰 원고지(`colors.paper`)를 올리고,
  포커스 시 테두리를 잉크로 진하게 합니다(`colors.accent`).
  다크 시절에는 "한 단계 밝게"였는데, 라이트에서는 방향이 반대라 **테두리로만** 표현합니다.

## 피드백

| 상황 | 무엇을 쓰나 |
|---|---|
| 결과 알림 (신고 접수, 티켓 소모) | `showToast(msg, 'ok'\|'warn'\|'error')` |
| 되돌릴 수 없는 동작 확인 | `components/Confirm.js` |
| 목록형 선택 (신고 사유, 사건 메뉴) | `components/ActionSheet.js` |

**`Alert.alert`을 쓰지 마세요.** RN Web에서 아무것도 띄우지 않아, 계정 삭제·항소가
웹에서 조용히 무시됐습니다. 코드에 `Alert`은 더 이상 없습니다.

## 컴포넌트 규약

- **판결문을 그릴 땐 `OpinionCard`** — 사건 상세 · 법원 피드 · 판례집 · 개표가 전부 이걸 씁니다.
  새로 그리지 마세요.
- **사람 이름이 나오면 `Avatar`** — 닉네임 해시로 색과 두 글자를 정하므로, 같은 사람은
  어느 화면에서든 같은 인장이 됩니다.
- **탭이 필요하면 `Segmented`** — 화면마다 제각각이던 필터 줄을 통합한 것입니다.
  **아이콘은 받지 않습니다.**
- **탭 화면 상단은 `ScreenHeader`** — 제목 + 아래 설명 한 줄 + 우측 액션.
- **사건 목록은 `CaseList` + `CaseCard`** — 직접 행을 그리지 마세요.
- **확정 표식은 `Stamp` / `StampChip`** — 목록처럼 높이가 아까운 자리에는 `StampChip`.

## 접근성

모든 `Pressable`에 `accessibilityRole`과 **한국어** `accessibilityLabel`을 답니다.
선택 상태가 있으면 `accessibilityState={{ selected }}`도 붙이세요.
게이지에는 `accessibilityRole="progressbar"` + 값을 읽어주는 라벨.

## 하지 말 것

1. **`View`에 함수형 style을 넘기지 마세요.**
   `style={({pressed}) => [...]}` 는 `Pressable`만 지원합니다. `View`에 넘기면
   **에러 없이 통째로 무시돼** 배경·테두리가 사라집니다. `ui.js`의 `Card`가 이것 때문에
   앱 전역에서 밋밋하게 렌더되고 있었습니다.

2. **`LayoutAnimation`을 쓰지 마세요.**
   New Architecture(Fabric)에서 무효이고 경고까지 뜹니다. `Animated`로 직접 하세요.
   (`components/OpinionCard.js`의 반박 스레드가 이 경우였습니다.)

3. **강조에 채도색을 쓰지 마세요.** 강조는 `colors.accent`(잉크)입니다.
   버튼·라벨·아이콘에 적/녹/주황을 쓰면 유죄·무죄·초박빙 신호가 묻힙니다.
   색은 뜻이 있을 때만.

   **목록 행에 법원 색을 쓰지 마세요.** 한 화면에 6색이 섞이면 제목이 안 읽힙니다.
   법원 색은 법원을 길드로 다루는 화면(법원 탭·대항전·필터·투고 선택)에서만 씁니다.

4. **그라디언트와 그림자를 쓰지 마세요.** 위 「함께 걷어낸 것」 참고.

5. **웹 기본 포커스 링** — RN Web은 입력에 파란 outline을 그립니다.
   `TextInput` style 배열 끝에 `inputReset`을 넣으세요.

6. **누를 수 있는 것 안에 누를 수 있는 것을 넣지 마세요.**
   웹에서 `<button>` 중첩이 되어 콘솔 경고가 뜨고, 스크린리더는 바깥 버튼 하나로만 읽습니다.
   형제로 두세요 — 사건 행의 북마크가 그래서 행 `Pressable` 밖에 있습니다.
   (표적 40dp는 지키되 **음수 세로 마진**으로 행 높이를 먹지 않게 합니다.)

7. **라이트에서 누름을 투명도로 표현하지 마세요.**
   투명도를 낮추면 요소가 배경 쪽으로 **밝아져** "눌렸다"의 반대로 읽힙니다.
   목록 행·카드는 `press.surface`(배경 하이라이트)를 씁니다.

8. **자동 높이 입력의 무한 렌더 루프** — `onContentSizeChange` 측정값에 여백을 더해
   `minHeight`로 되먹이면 매 프레임 높이가 커지며 루프에 빠집니다.
   **콘솔 에러 없이 화면 전체가 빈 페이지**가 되므로 원인 찾기가 고약합니다.
   측정값을 그대로 `height`로 쓰고, 1px 초과 차이일 때만 setState 하세요.
