# 읽고 참여하기 쉬운 UI 개편

## 참고한 사례

- [Hacker News](https://news.ycombinator.com/): 제목을 먼저 읽고 참여 수를 뒤에서 확인하는 정보 위계. 이 앱은 한국어 사연이 길어 제목 두 줄과 더 넓은 행 간격을 사용한다.
- [Reddit 피드 안내](https://support.reddithelp.com/hc/en-us/articles/360043043552-What-s-the-difference-between-r-all-r-popular-news-and-my-home-feed): 관심 목적에 따라 피드를 구분하는 구성. 오늘의 사건·토론·종료 사건 필터를 유지한다.
- [Duolingo의 성취 연출](https://blog.duolingo.com/streak-milestone-design-animation/): 참여 성취를 알아보기 쉽게 표현하는 사례. 진행 현황과 완주 안내를 사연 진입 버튼 가까이에 배치한다. 효과 자체가 이 앱에서도 입증된 것은 아니다.

## 반영한 변경

- 홈 첫 화면에 다음 사연 제목과 미리보기를 배치한다. 안내는 작은 참여 방법 링크로 제공하며, 하단 이용 안내는 항상 유지한다.
- 홈 제목은 18px/27px, 공용 사건 목록 제목은 16px/25px 두 줄로 표시한다. 상세 사건 번호는 목록의 핵심 정보에서 제외한다.
- 베이지는 화면 바탕, 흰색은 읽기 영역으로 사용한다. 색을 늘리기보다 글자 크기와 여백으로 우선순위를 구분한다.
- 참여한 사건의 전체 투명도를 낮추지 않는다. 메타 정보는 줄바꿈하고 북마크 터치 영역은 44px를 확보한다.
- 공용 버튼 최소 높이를 48px로 하고 긴 라벨의 줄바꿈을 허용한다.
- 결과 연출을 650ms로 줄이고 건너뛰기를 제공한다. 가상의 투표 이력을 실제 재생하는 것처럼 표현하지 않는다.
- 소수의견을 오답이라고 부르지 않는다. 기존 보상 규칙은 유지하되 초박빙 보너스는 적중했을 때만 안내한다.

## 확인 범위

디자인 토큰 검사와 웹 번들 빌드로 정적 오류를 확인한다. 브라우저 연결이 제공되지 않아 실제 화면의 겹침·키보드 이동·확대 글꼴은 시각 검증하지 못했다. 출시 전 320/390/768/1440px에서 홈, 목록, 판결 완료 화면을 확인해야 한다. 참여율 개선 여부는 실제 사용자 테스트로 확인한다.
