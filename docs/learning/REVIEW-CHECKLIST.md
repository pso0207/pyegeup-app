# 코드 리뷰 체크리스트

모든 항목을 매번 확인할 필요는 없습니다. 이번 기능과 관련된 항목에 표시합니다.

## 요청과 응답

- [ ] URL, HTTP 메서드, 상태 코드가 의미에 맞다.
- [ ] 요청 DTO가 형식 오류를 검증한다.
- [ ] Entity를 외부 응답으로 직접 내보내지 않는다.
- [ ] 오류 응답 모양이 다른 API와 같다.
- [ ] 비밀번호, 내부 점수, 삭제 정보 등 비공개 필드가 노출되지 않는다.

## 책임

- [ ] Controller는 HTTP 변환만 담당한다.
- [ ] Service가 유스케이스와 비즈니스 규칙을 담당한다.
- [ ] Repository는 저장과 조회를 담당한다.
- [ ] 메서드와 클래스 이름만 보고 의도를 이해할 수 있다.
- [ ] 중복 로직을 제거하려다 불필요한 추상화를 만들지 않았다.

## 데이터와 트랜잭션

- [ ] DB 제약과 애플리케이션 검증이 서로 보완한다.
- [ ] 함께 성공해야 하는 변경이 같은 트랜잭션에 있다.
- [ ] 동일한 요청이 두 번 오거나 동시에 와도 데이터가 깨지지 않는다.
- [ ] 날짜와 시간대가 명시적이다.
- [ ] 목록 쿼리에 불필요한 N+1이나 전체 조회가 없다.

## 보안

- [ ] 요청 body의 사용자 ID를 그대로 신뢰하지 않는다.
- [ ] 본인 소유 자원인지 서버에서 확인한다.
- [ ] 비밀번호와 토큰이 로그나 Git에 남지 않는다.
- [ ] 인증 실패와 권한 부족을 구분한다.
- [ ] 숨겨진 화면이 아니라 API 자체가 권한을 막는다.

## 테스트

- [ ] 정상 사례가 있다.
- [ ] 존재하지 않는 데이터 사례가 있다.
- [ ] 경계값과 잘못된 입력 사례가 있다.
- [ ] 중복·동시 요청처럼 실제로 위험한 사례가 있다.
- [ ] 테스트 이름이 조건과 기대 결과를 설명한다.
- [ ] 테스트가 구현 세부사항보다 외부 동작을 검증한다.

## 내가 설명할 수 있는가

- [ ] 요청 한 건의 흐름을 화살표로 그릴 수 있다.
- [ ] 주요 어노테이션이 왜 필요한지 설명할 수 있다.
- [ ] SQL이 대략 어떻게 실행될지 예상할 수 있다.
- [ ] 테스트 하나를 보지 않고 다시 쓸 수 있다.
- [ ] 현재 구현이 보장하지 못하는 상황을 하나 말할 수 있다.
