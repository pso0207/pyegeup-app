# AI 협업 요청서

프로젝트 루트의 `AGENTS.md`가 기본 지침입니다. 아래 문장은 기능을 요청할 때 복사해서 사용합니다.

## 실습 프로젝트를 이어갈 때

처음 시작:

```text
실습 0 시작해줘
```

다음 날 이어서 시작:

```text
docs/learning/PROGRESS.md를 읽고 다음 실습을 이어서 해줘.
파일과 테스트는 네가 실제로 구현하고, 내가 리뷰할 부분과 작은 수정 과제를 남겨줘.
```

실습의 범위와 완료 조건은 [PRACTICE-PROJECT.md](PRACTICE-PROJECT.md)에 있습니다.

## 새 기능 구현

```text
나는 Java/Spring/MySQL을 배우는 중이야.
[기능 이름] 하나만 세로로 구현해줘.

구현 전에 다음을 알려줘:
- 이 기능의 요청 → 응답 흐름
- 변경할 파일과 각 파일의 책임
- 서버가 검증해야 할 규칙

구현할 때:
- 정상 사례와 중요한 실패 사례 테스트를 같이 작성해줘.
- 과도한 추상화와 Lombok은 피하고 초보자가 읽을 수 있게 작성해줘.
- 실행 가능한 코드만 만들고, 실제 테스트 결과를 알려줘.
- 기존 도메인 규칙은 임의로 바꾸지 마.

구현 후:
- 내가 집중해서 리뷰할 코드 세 곳을 알려줘.
- 이해 확인 질문 다섯 개와 직접 작성할 작은 과제 하나를 줘.
- docs/learning/REVIEW-LOG.md에 기록을 추가해줘.
```

## 힌트만 받기

```text
정답 코드를 작성하거나 파일을 수정하지 마.
내 접근에서 잘못된 가정만 알려주고, 다음 한 단계의 힌트와 확인 질문을 줘.
컴파일 오류라면 오류가 뜻하는 것과 확인 순서만 설명해줘.
```

## 코드 리뷰

```text
파일을 수정하지 말고 코드 리뷰만 해줘.
중요도 순으로 문제를 정리하고 파일과 위치를 표시해줘.
각 문제마다 실제 위험, 재현 조건, 최소 수정 방향을 알려줘.
보안·데이터 유실·트랜잭션·동시성·요구사항 위반·테스트 누락을 먼저 봐줘.
마지막에 잘 분리된 책임과 내가 배워야 할 개념도 알려줘.
```

## 내가 작성한 코드 테스트

```text
내 구현을 바로 고치지 말고 먼저 테스트를 추가해서 문제를 재현해줘.
테스트가 실패하는 이유를 설명한 뒤 내가 고칠 수 있도록 힌트만 줘.
내가 '구현해줘'라고 말하면 그때 최소 수정하고 테스트를 다시 실행해줘.
```

## 리팩터링

```text
기능을 추가하지 말고 현재 동작을 보존해줘.
먼저 기존 테스트를 실행하고, 한 번에 코드 냄새 하나만 고쳐줘.
변경 전후 책임 구조와 장단점을 설명하고 테스트를 다시 실행해줘.
추상화가 실제 중복이나 변경 이유를 줄이지 못하면 만들지 마.
```
