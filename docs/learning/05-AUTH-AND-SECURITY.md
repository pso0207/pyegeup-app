# 05. 인증과 권한

## 이번 단계의 결과

로그인한 사용자를 서버가 식별하고, 본인의 권한으로만 판결하거나 글을 삭제합니다. CRUD가 안정된 뒤 인증을 붙입니다.

## 구분하기

- 인증(Authentication): 이 요청을 보낸 사람이 누구인지 확인
- 인가(Authorization): 그 사람이 이 행동을 해도 되는지 확인
- 비밀번호 해시: 원문 비밀번호를 복구할 수 없게 저장
- 액세스 토큰: 요청마다 사용자 신원을 전달
- 리프레시 토큰: 액세스 토큰을 새로 발급받기 위한 장기 자격 증명

## 단계별 구현

1. 회원가입과 중복 이메일 검증
2. 비밀번호 해시 저장
3. 로그인 성공·실패
4. 인증 필터에서 사용자 식별
5. 임시 사용자 ID 제거
6. 본인 자원 권한 검사
7. 만료·위조·권한 부족 테스트
8. 토큰 저장과 로그 노출 여부 점검

## AI에게 요청할 범위

인증은 한 번에 전부 요청하지 않습니다.

```text
이번에는 회원가입만 구현해줘. 이메일 중복과 비밀번호 해시 테스트까지 포함해줘.
토큰 로그인은 다음 단계로 남겨줘. 보안상 중요한 결정을 설명해줘.
```

다음 회차:

```text
기존 회원가입 코드 위에 로그인과 액세스 토큰 검증만 추가해줘.
비밀키는 코드에 넣지 말고 환경 변수로 받아줘.
성공, 틀린 비밀번호, 만료·위조 토큰 테스트를 작성해줘.
```

## 리뷰 질문

1. 비밀번호를 암호화가 아니라 해시한다고 표현하는 이유는 무엇인가?
2. 로그인 실패 이유를 너무 자세히 알려주면 어떤 문제가 있는가?
3. 토큰 서명 키가 Git에 올라가면 어떻게 해야 하는가?
4. 사용자 ID를 요청 body에서 받으면 왜 위험한가?
5. 401과 403은 어떻게 다른가?

## 직접 재작성 과제

본인 사연만 삭제할 수 있는 권한 테스트를 작성합니다. 다른 사용자의 ID로 요청했을 때 DB 데이터가 남아 있는지도 확인합니다.
